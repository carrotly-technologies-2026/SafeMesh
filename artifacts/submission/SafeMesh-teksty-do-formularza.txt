Problem i rozwiązanie

Problem

Wklej cały poniższy tekst. Statystyka jest historyczna i ma podane źródło.

During a crisis, a mobile-network outage can cut people off from warnings and the information needed to act on them. This is a documented risk: ITU's December 2022 interim assessment of Ukraine reported that almost 11% of mobile operators' base stations were out of service. This historical example illustrates the vulnerability of communications infrastructure; it is not a current estimate for Poland.

Residents need to retain trustworthy warnings and find local protective-point information even when connectivity is unavailable. Forwarded messages add a second problem: recipients may be unable to tell whether the text was altered. SafeMesh addresses these connected needs: offline access, message authenticity and practical local reference information.

Source: ITU, Interim assessment on damages to telecommunication infrastructure and resilience of the ICT ecosystem in Ukraine, December 2022.

Solution

Wklej opis działającego prototypu i jego obecnych granic.

SafeMesh is a native HarmonyOS prototype for civilian crisis preparedness. It combines digitally signed alerts, an offline map and a store-and-forward relay engine designed to pass verified warnings between nearby phones. Each receiver checks an ECDSA P-256/SHA-256 signature before accepting an alert. Altered or expired messages are rejected, and duplicates are not forwarded again.

The bundled map works from first launch without downloading data. It covers central Kraków and includes 40 protective-point records from Poland's State Fire Service (PSP), address search and a saved place. The app also provides Polish and English interfaces, appearance settings and optional foreground location.

A public NearLink API adapter is implemented. The emulator demonstrates three independent relay engines in a clearly labelled A → B → C simulation; physical phone-to-phone radio exchange remains unverified. Alerts are signed exercises, with no official RCB integration. Map records do not confirm current access or condition, and the app does not calculate evacuation routes.

What's done so far and goal of your project

Wklej całość. Pierwsze zdanie oparto na Twojej odpowiedzi, że przed wydarzeniem nic nie istniało. Przed wysłaniem upewnijcie się wspólnie, że odpowiada to faktycznej historii zespołu.

Before the event: SafeMesh had no existing implementation or prototype. The project was started during the hackathon.

Completed during the event so far: we built and ran a native ArkTS/ArkUI application with on-device alert signature verification, rejection of altered and expired messages, duplicate suppression and local persistence. We added a bundled Kraków map with 40 PSP protective points, address search, a saved place, optional foreground location and persistent language/theme settings. The relay engine includes cached-message synchronization, bounded retries and receiving-app acknowledgements. Recorded validation includes 61 passing automated host checks, six native signature/relay checks and a 90-second emulator demonstration.

Our event goal is a reproducible, demonstrable prototype showing how verified warnings and local protective-point information can remain available without mobile internet, with source code, run instructions and a short demo for the jury.

The next milestone after the emulator prototype is a controlled test on compatible physical phones: A passes a signed alert to B, A disconnects, and B later delivers it to C without internet. Physical NearLink exchange and background delivery are not demonstrated. Future operational deployment would require work with public-safety organisations on authorised issuing, data maintenance and field validation.

Co potwierdza opis

Dokumentacja i kod pokazują aplikację natywną, weryfikację podpisów, trwały zapis, mapę offline i adapter NearLink. Wyniki 61 testów oraz 6/6 kontroli pochodzą z istniejących logów i dokumentacji walidacji — nie z nowego uruchomienia testów na potrzeby tego PDF.

Najważniejsze ograniczenie prezentacji: A → B → C działa jako symulacja na emulatorze. Nie opisujcie tego jako przetestowanego przesyłu radiowego na trzech telefonach. Nie ma też gwarancji dostarczania w tle ani potwierdzania otwarcia punktu schronienia na żywo.

Instructions on how to open project

Wklej poniższy opis wraz z komendami. Przykładową ścieżkę Studio i numer urządzenia trzeba dopasować do komputera osoby uruchamiającej projekt.

1. Obtain the submitted source code (repository or SafeMesh-source.zip). Open the project folder containing build-profile.json5 and oh-package.json5 in DevEco Studio.

2. Follow the fresh-machine setup in README.md. The tested environment is DevEco Studio 6.1.1, Huawei HarmonyOS SDK API 24 including HMS kits, Node.js 24 and DevEco CLI 1.3.4 with the organiser's patches. A plain OpenHarmony SDK alone does not include NearLink Kit. Start an API 24 phone emulator.

3. Open PowerShell in the project folder. Set your Studio path and list connected devices:

$env:DEVECO_CLI_STUDIO_PATH = 'C:\path\to\DevEcoStudio'
devecocli.cmd device list --format json
powershell -ExecutionPolicy Bypass -File scripts/run-demo.ps1 `
  -Device '127.0.0.1:5555' -RefreshDrill

Use the device serial reported by device list. The helper refreshes the signed demo fixtures, builds the app, installs it and launches org.safemesh.alerts/EntryAbility.

4. The default interface is Polish. Open the top-right gear and select English if needed. On Home, receive a signed drill. On Map, search and save a protective point. On Relay, run the signed relay drill: the expected result is 6/6 checks passed. Check hardware to see the emulator's unavailable NearLink radio status. This is expected; physical radio transfer requires compatible phones.

5. The supplied SafeMesh-demo.hap is an unsigned debug package validated on the emulator. Physical phones require development signing. The prebuilt signed drill expires on 2026-10-06 at 15:19:32 UTC. The -RefreshDrill command generates a fresh 72-hour drill and rebuilds the app.

For reproducible host tests, ArkTS checks, lint and build, run scripts/check.ps1 -Build. See README.md, artifacts/VALIDATION.md and AI_WORKFLOW.md for setup details, recorded results and development-tool disclosure.

Proponowany układ krótkiej prezentacji

1. Problem — brak sieci oznacza utratę dostępu do ostrzeżeń i informacji lokalnej; jedna historyczna statystyka ITU ze źródłem.

2. SafeMesh — podpisane alerty, mapa offline, docelowo przekazywanie ostrzeżeń między pobliskimi telefonami.

3. Demo — odbiór ćwiczenia, wyszukanie punktu, zapis, wynik 6/6 w symulacji A → B → C.

4. Dowody — 40 rekordów PSP, 61 testów hostowych, natywny emulator, gotowy kod i instrukcja startu.

5. Dalszy krok — test na fizycznych urządzeniach; jawne ograniczenia NearLink, ćwiczeniowego wystawcy i aktualności mapy.
