# SafeMesh readiness and HarmonyOS UX audit

2026-10-03, updated with the v1.1 validation checkpoints. This document preserves the initial audit and tracks the subsequent implementation. Scope: source review, recorded native evidence, official Huawei documentation, host checks and the hackathon requirements. It is not Huawei certification or a complete accessibility/security assessment. Implemented behavior, measured results and outstanding checks are distinguished below.

## Assessment

SafeMesh is a working native ArkTS/ArkUI emulator prototype. The follow-up implements the concrete UI and functional corrections identified in the first audit, including PL/EN copy, system appearance, larger controls, accessible alternatives to the map, reliable saved-point state, optional foreground location and a bounded delivery queue. It is not an operational emergency-warning system, a proven physical mesh, or an app certified against every HarmonyOS/AppGallery requirement.

Final verified application source: **`1bd015dc9ca3cea9c230b78b0253abfc61a8bcae`**. The full host checkpoint passed **61 tests across seven suites, with zero failures**: [v1.1 results](logs/v11-checks.log). The final native-symbol navigation build passed **ArkTS with no errors in 17 files** (separate permission/exception advisories remain), **lint with zero issues**, HAP build and emulator install/launch **Smoke: PASS**. See [ArkTS](logs/v11-release-arkts.log), [lint](logs/v11-release-lint.log), [build](logs/v11-release-build.log) and [run](logs/v11-release-run.log). A fresh clone at that exact source repeated all 61 host tests, ArkTS 17/0, lint 0 and build successfully on the same computer/SDK. The earlier 40-test, 58-test and Settings-build runs remain historical evidence.

The final navigation has **four bottom destinations: Home, Map, Relay and Guide**, using native `SymbolGlyph` icons. A top-right native gear opens a dedicated Settings screen with saved PL/EN and Light/Dark/System choices. All four tabs, Settings and return navigation passed native checks, including measured Huge 1.45 text. Screenshots from earlier checkpoints may show intermediate navigation; final evidence uses `v11-release-*` names. A 90-second live emulator video and same-host clean-checkout verification are complete.

The visual identity is coherent, but conformity involves accessible interaction, meaningful information hierarchy, system settings, readable typography and adaptation to the supported device configurations. Custom branding and a custom tab bar are not inherently prohibited. Native Tabs, system symbols and resource tokens are useful implementation choices, not blanket requirements to copy Huawei's visual appearance. The manifest targets phones; tablet/PC support is not automatically required.

## Functional improvements implemented after the audit

- **Delivery queue:** newly connected peers receive every still-valid verified cached alert, rather than only the visible alert. Matching per-connection receipt tokens, serialized batches, at most three attempts per item/connection, bounded native-send waits, retry exhaustion, expiry pruning and reconnect synchronization are implemented. Success ACKs follow verified accepted/duplicate content. They mean a receiving application retained verified content in memory, not that a person read it, that a peer identity is authenticated or that durable storage succeeded. Persistence failures remain separate. Fourteen host delivery tests exercise actual source with controlled loss/clocks, including stop during suspended native sends/startup. See [security evidence](research/security.md).
- **Restoration and storage:** radio startup waits for replay-state restoration; read failure pauses forwarding and permits retry. Existing bounded chunk/generation storage remains in use. Queues belong to the foreground session; verified alert snapshots persist privately.
- **Optional location:** an explicit action requests one foreground LocationKit fix. Permission, service, coordinate validity, reported accuracy and map coverage are checked. Only positions inside the bundled extent with accuracy at most 250 m replace the labelled demo origin. Denied/unavailable/inaccurate/outside-pack outcomes retain the prior origin and show status. Position is neither saved nor relayed. This is not continuous tracking or validated physical positioning. See [location/save evidence](research/location-and-saved-points.md).
- **Video:** [record-demo.py](../scripts/record-demo.py) captured the [final live emulator demonstration](../dist/SafeMesh-demo.mp4): 90 seconds of H.264 at 478×1030, 15 fps, 1,350 frames and zero late frames. Capture is restricted to the Emulator.exe client window, using Studio's bundled FFmpeg. This is app/emulator evidence, not a physical-radio test. See [capture metadata](logs/v11-demo-capture.json) and [capture instructions](research/demo-capture.md).
- **Check helper:** [check.ps1](../scripts/check.ps1) discovers all host suites, runs ArkTS/lint and optionally builds the HAP. Recording/build artifacts stay local and ignored by Git.

## Functional scope still outstanding

- **Physical NearLink:** only an in-process relay simulation was exercised. The native adapter still needs compatible-device validation, including permission/radio state, discovery, MTU framing, interruption and multi-device forwarding.
- **Mesh discovery:** API 24 still requires the other device's exact name and a selected connection. Automatic discovery of every participant is absent. The new full-cache queue and receipt policy have host coverage; compatible phones must validate actual packet delivery, loss/reconnect, receipts and traffic behavior. Receipt tokens do not authenticate peer identity or prove end-to-end dissemination.
- **Lifecycle:** continuous background/locked-screen delivery and measured battery/congestion behavior are not implemented or demonstrated. The foreground relay stops when the page is hidden; host interruption tests are not physical lifecycle evidence.
- **Authority:** the trusted signer is a demo issuer only. Official alerts, issuer operations, key rotation/revocation and trusted-time policy are absent. Signatures do not prevent radio jamming or message dropping.
- **Maps:** 40 real PSP reference points and vector data remain a selected Kraków subset. Optional one-shot device location is implemented with accuracy/coverage gates, but continuous tracking and actual physical positioning accuracy are not demonstrated. Route planning, in-app regional pack download/update and live access verification remain absent. Bundling provides first-launch offline availability.
- **Distribution:** the current unsigned HAP was accepted by the emulator. Physical-phone signing and AppGallery readiness were not validated.
